---
title: LAG / LEAD
description: Read a value from a previous or following row without a self-join — the basis of period-over-period comparisons.
---

## Syntax

```sql
LAG(expression [, offset [, default]]) OVER (
  [PARTITION BY partition_expression, ...]
  ORDER BY sort_expression [ASC | DESC], ...
)

LEAD(expression [, offset [, default]]) OVER ( ... )
```

<Parameters>
  <Param name="expression" type="any" required>
    The value to read from the neighbouring row.
  </Param>
  <Param name="offset" type="integer">
    How many rows back (`LAG`) or forward (`LEAD`) to look. Defaults to `1`.
  </Param>
  <Param name="default" type="same type as expression">
    Returned when there's no such row (start/end of partition). Defaults to `NULL`.
  </Param>
</Parameters>

## What it does

`LAG()` returns `expression` from `offset` rows **before** the current row in
the window's order; `LEAD()` looks `offset` rows **after**.

<SqlRunner query={`SELECT
  month,
  revenue,
  LAG(revenue) OVER (ORDER BY month)  AS prev_month_revenue,
  revenue - LAG(revenue) OVER (ORDER BY month) AS mom_change
FROM monthly_revenue
ORDER BY month;`} />

January has no prior row, so `prev_month_revenue` and `mom_change` are `NULL`
there — usually the right behavior, since there's nothing to compare against.

## Per partition

<SqlRunner query={`SELECT
  customer_id,
  order_date,
  order_id,
  LAG(order_id) OVER (
    PARTITION BY customer_id
    ORDER BY order_date, order_id
  ) AS prev_order_id
FROM orders
ORDER BY customer_id, order_date;`} />

`PARTITION BY customer_id` means `LAG` never looks across a customer boundary
— the first order for each customer correctly has no "previous" order.

## Supplying a default instead of NULL

<SqlRunner query={`SELECT
  month,
  revenue,
  LAG(revenue, 1, 0) OVER (ORDER BY month) AS prev_month_or_zero
FROM monthly_revenue
ORDER BY month;`} />

## Gotchas

- **The window `ORDER BY` defines "previous"** — without a deterministic
  order (add a tiebreaker), the row `LAG` picks on a tie is arbitrary.
- **Boundary rows need a decision.** `NULL`, `0`, or a supplied `default` all
  mean different things downstream — pick deliberately, don't let it default silently.
- **`PARTITION BY` resets the lookback.** Omit it only when you actually want
  to read across group boundaries.

## Safety check before shipping

- decide what the boundary rows should show — NULL, 0, or a supplied default
- confirm the window ORDER BY is deterministic
- check whether the comparison should reset per partition
