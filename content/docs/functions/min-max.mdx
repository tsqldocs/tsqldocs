---
title: MIN / MAX
description: The smallest or largest value in a group — for numbers, dates, and text — and how to get the whole row that owns it.
---

## Syntax

```sql
MIN(expression)
MAX(expression)
```

<Parameters>
  <Param name="expression" type="any orderable type" required>
    Numbers, dates, or text. `NULL`s are ignored; text compares lexicographically.
  </Param>
</Parameters>

## What it does

<SqlRunner query={`SELECT
  customer_id,
  MIN(order_date) AS first_order,
  MAX(order_date) AS last_order,
  MAX(amount)     AS largest_order
FROM orders
GROUP BY customer_id
ORDER BY customer_id;`} />

## MIN/MAX don't tell you the rest of the row

`MAX(amount)` above is the largest amount **per customer** — it doesn't say
which `order_id` that was, and other columns in the same `SELECT` aren't
guaranteed to line up with it. To get the full row that owns the extreme
value, rank and filter instead:

<SqlRunner query={`SELECT customer_id, order_id, amount
FROM (
  SELECT o.*,
    ROW_NUMBER() OVER (
      PARTITION BY customer_id
      ORDER BY amount DESC, order_id DESC
    ) AS rn
  FROM orders o
) ranked
WHERE rn = 1
ORDER BY customer_id;`} />

This is the [top N per group](/docs/recipes/top-n-per-group) pattern with N = 1.

## Text sorts lexicographically

`MAX('9')` is greater than `MAX('10')` as **text** — `'9' > '10'` character by
character. If a column holding numeric-looking text is compared this way,
cast it: `MAX(CAST(code AS INTEGER))`.

## Gotchas

- **NULLs are ignored**; a group of all-`NULL` values returns `NULL`.
- **Text vs numeric sort order** — confirm the column type sorts the way the
  query assumes.
- **Don't assume other `SELECT`ed columns match the MAX row** — see above.

## Safety checklist

- confirm the column type sorts the way you expect (numeric vs text vs date)
- decide whether an all-NULL group should yield NULL or a fallback
- rank the rows if you need the whole row, don't assume other columns line up
