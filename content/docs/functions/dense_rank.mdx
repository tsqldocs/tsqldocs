---
title: DENSE_RANK
description: Rank rows while keeping ties together and leaving no gaps in the sequence.
---

## Syntax

```sql
DENSE_RANK() OVER (
  [PARTITION BY partition_expression, ...]
  ORDER BY sort_expression [ASC | DESC], ...
)
```

<Parameters>
  <Param name="PARTITION BY" type="expression, …">
    Optional. Restarts the ranking for each group. Without it the whole result
    set is one partition.
  </Param>
  <Param name="ORDER BY" type="expression [ASC|DESC], …" required>
    Defines the ranking order. Rows that are equal under this ordering are a
    tie and share a rank.
  </Param>
</Parameters>

`DENSE_RANK()` itself takes no arguments — the `OVER (…)` window clause does all the work.

## What it does

`DENSE_RANK()` gives tied rows the same rank, then continues with the next integer without skipping.

Example: values `10, 10, 20` become ranks `1, 1, 2`.

## Example

```sql
SELECT
  product_id,
  category_id,
  sales,
  DENSE_RANK() OVER (
    PARTITION BY category_id
    ORDER BY sales DESC
  ) AS sales_tier
FROM product_sales;
```

<SqlRunner query={`SELECT
  product_name,
  category_id,
  sales,
  DENSE_RANK() OVER (PARTITION BY category_id ORDER BY sales DESC) AS dense_tier,
  RANK()       OVER (PARTITION BY category_id ORDER BY sales DESC) AS rank_tier
FROM product_sales
ORDER BY category_id, sales DESC;`} />

Category 1 has two products tied at `400`. `DENSE_RANK` gives the next product
tier `2`; `RANK` gives it `3`.

## Safety questions

- do you want distinct value tiers, or a strict per-row ordering?
- is the `ORDER BY` stable enough for the ranking to be reproducible?
- should ties share a tier, or be broken with a secondary sort column?
